### T02 · Screen launcher, views half                                 size: M
Place in the tree: product › foundations › testing › any screen in any state (layer 8)
Repo · branch: NPRdoinglaundry · ui/T02-screen-launcher
Needs: T01; an integrator PR adding one hook in the app root (`RetrospectApp.swift`) that, in DEBUG and UI-test builds only, shows `ScreenLauncher` when `-Screen` is present
Unblocks: every page byte's UI and accessibility tests; every headless check; the integrator's wiring PRs (plumbing adds `-Data live`)

Why: every state of every screen can be opened directly, without tapping through the app. Tests, headless screenshots and reviews all reach the exact state they need, in one launch.

Inputs:
- Testing: [testing.md](../testing.md) §1 layer 8, §3 T02
- Code anchors: `RetrospectApp.swift:79–120` (the existing `-DesignLab`, `-AnimationPreview` and other flags: same pattern); `DesignV2Switches.swift:51` (`-DesignV2Off`)
- Contract: none (sample data only; `-Data live` is plumbing's half)

Spec:
- **Arguments:**

  | Argument | Values | Default |
  |---|---|---|
  | `-Screen <id>` | a page id (`JR-1` … `EX-4`, `PI1`, `PI2`, `PX`) or `gallery.<component id>` (`gallery.C26`) | none (normal app) |
  | `-Data <source>` | `sample` (yours) · `live` (plumbing's, later) | `sample` |
  | `-State <name>` | the flow's scenario name, for example `full`, `dayOne`, `offline`, `loading`, `error.network`, `briefMaking`, `briefQuiet`, `guessOffered`, `tookWaiting`, `deleteDialog` | `full` |
  | `-Appearance` | `light` · `dark` | system |
  | `-ContentSize` | a `UIContentSizeCategory` raw value, for example `UICTContentSizeCategoryAccessibilityXL` | system |
  | `-ReduceMotion` | `YES` (sets the environment flag your components read) | system |

- **Registry:** `Features/Launcher/ScreenRegistry.swift` maps each id to a builder `(DataSource, Scenario) -> AnyView`. Each flow registers its own screens from its own folder (`Features/Journal/JournalScreens+Launcher.swift`), so adding a page never edits another flow's file.
- **Unknown id or state:** a plain screen listing the valid ids and states, which is also the test's failure message. It never crashes.
- **Guard:** the whole folder is compiled only under `#if DEBUG || UITESTS`. A release build has no launcher. (A test proves the symbol is absent from the release build: `nm` on the Release product, run in CI by the integrator.)
- **Accessibility identifiers:** every page's root gets `screen.<id>`, and each state's distinguishing element gets an id named on its page card, so UI tests assert by id.

Steps:
1. Argument parsing (a pure function, unit tested).
2. Registry and unknown-id screen.
3. Gallery entries for merged components.
4. Ask the integrator for the app-root hook.
5. XCUITest smoke test.

Acceptance:
- `-Screen gallery.C01 -State pressed` opens the button gallery on its pressed state.
- `-Screen nope` shows the list, with no crash.
- `-Appearance dark -ContentSize …AccessibilityXL` applies both.
- A Release build contains no `ScreenLauncher` symbol.
- Parsing has no side effects outside the launcher (the old app is unchanged without `-Screen`).

Tests:
- (unit) the arguments are parsed into screen, data, state, appearance and size
- (unit) unknown values are reported, never thrown
- (unit) a missing `-Data` defaults to sample
- (UI) launching with `-Screen gallery.C01` shows the button gallery
- (UI) launching with an unknown screen shows the list of valid screens
- (UI) launching without `-Screen` shows the normal app

Proof in the PR:
- the three UI test results
- a headless screenshot of the gallery in dark AX3
- the `nm` output from the Release build

Watch out:
- Never read `UserDefaults` for these: launch arguments also land in the argument domain, but tests must not leak state between launches. Parse `ProcessInfo.processInfo.arguments` only.
- `-ContentSize` must be applied with `.environment(\.dynamicTypeSize, …)` on the root and `UITraitCollection` overrides for UIKit-backed views (the blur view), or the two disagree.
- Keep the old flags working; don't refactor them, since that's the integrator's file.
