### C39 · Shared states: loading, empty, error, offline                4 bytes × size S
Place in the tree: every flow › every data page › shared states
Repo · branches: NPRdoinglaundry · `ui/C39.1-skeleton`, `ui/C39.2-empty`, `ui/C39.3-error`, `ui/C39.4-offline`
Needs: T01 (and the `.rFrozen` flag from T01 for C39.1)        Unblocks: every page (P09 first)

Why: when something is loading, empty, broken or offline, the person sees the same calm, honest language everywhere. That means no spinners for content, no blank screens, and no invented data.

Inputs:
- Spec: `design-system/components/loading-and-empty.md`; reference §C39; motion-system §6 "Loading and empty"; craft §12.3
- Paper:
  - legacy "c5 · states, dark and access" `1XE-0` (the only full drawing: say so in each PR)
  - M3 key states for the drawer and entry `E4L-0`
  - the drawer's empty and no-results state `G7O-0`
  - the brief card's making and error states inside part 03, M3 `CEM-0`
- Contract: 00 (`Backend.Failure` cases and their plain messages)

Spec:

| Byte | What | Anatomy and values |
|---|---|---|
| **C39.1** `RSkeleton` | content-shaped bars | bars `surface.skeleton`, radius `radius.small` 6 (`RShape.rect`); a shine `surface.skeletonShine` sweeps left to right every `duration.shimmer` 1400 on `curve.move`; appears only after 400ms (`.task` with an injected clock); content replaces it with a 140ms cross-fade; "still working" (Geist 12 `text.label`) under it after 8s |
| **C39.2** `REmptyLine` | one serif line | display serif (`font.exposure.card`, `text.secondary`) saying what will be here and how it fills; at most one action (`RButton` text); arrives with `.rAppear` stagger, then stays still; never an illustration |
| **C39.3** `RErrorState` | what went wrong + "try again" | the empty layout: the message is `Backend.Failure.plainMessage` (Geist 500 12 `status.dangerText` inline, or the serif line full-page) + a neutral `RPill` "try again" with the `retry` glyph; `error` haptic once when it first appears |
| **C39.4** `ROfflineLine` | the offline line | Geist 12 `text.label` + `offline` glyph: "you're offline · showing what's saved" (pages) or "offline · new notes send when you're back" (drawer); grey, never red; blur-replaces in and out (`.rBlurReplace`) |

State table (shared):

| State | Look | Motion | Haptic |
|---|---|---|---|
| loading < 400ms | nothing (the previous content or blank canvas) | — | — |
| loading ≥ 400ms | skeleton | shimmer 1400 `curve.move` | — |
| loading ≥ 8s | + "still working" | blur-in 220 | — |
| loaded | content | 140ms cross-fade, no layout jump | — |
| empty | one serif line (+ one action) | `.rAppear` stagger | — |
| error | message + try again | blur-in | `error` (once) |
| try again pressed | pill 0.94 | `.rPress` | none |
| offline | offline line above the cached content | `.rBlurReplace` | — |
| dark | dark skeleton values | — | — |

Interaction table:

| Touch | Press | Haptic | Motion | Outcome | Reduce Motion |
|---|---|---|---|---|---|
| try again | 0.94 | none | `.rPress` | the page retries; the skeleton returns after 400ms | same |
| empty action | text dims | none | 80/240 | its outcome | same |

Accessibility:
- the skeleton reads "loading" once (a single element, `.updatesFrequently` off)
- the empty state reads its line
- the error reads its message, then "try again, button"
- the offline line is announced once when it appears (`AccessibilityNotification.Announcement`)
- AX3: skeleton bars follow the text sizes
- Reduce Motion: no shine; the bars pulse opacity 1 → 0.6 → 1 on `curve.move`
- Increase Contrast: bars one step darker

Steps: each byte separately — component, gallery state, snapshots, recording (C39.1).

Acceptance:
- No skeleton under 400ms.
- No spinner for page content anywhere.
- The error copy comes from `Backend.Failure`, never written in the view.
- No illustration and no exclamation marks.
- Each byte matches the legacy node and the M3 cards (differences listed).

Tests:
- (unit) the skeleton isn't shown when content arrives in 399ms
- (unit) the skeleton is shown at 400ms and "still working" at 8s
- (snapshot) a frozen skeleton matches in light, dark and ax3
- (snapshot) the empty line with and without an action
- (snapshot) the error state for `.network` and `.server`
- (snapshot) the offline line, both copies
- (UI) the offline line is announced once

Proof in the PR: standard proof, plus the shimmer recording and the Reduce Motion pulse recording (C39.1).

Watch out:
- The 400ms delay must use the injected clock, or tests are flaky.
- The cross-fade must not change layout height. The skeleton is the content's shape, so measure it against the loaded content's snapshot.
- Pull to refresh (orb vs mark) is a later decision. Not in these bytes.
